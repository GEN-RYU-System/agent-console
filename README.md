# agent-console

Local console for running parallel Claude Code sessions (Orca-inspired, lightweight).

## 定期実行（v0.7.0、v0.18.0 で「毎回新しいセッション」に変更）

「定期実行」タブは、Asia/Tokyo の曜日・時刻になると新しい Claude Code セッションを1つ開き、Claude が入力待ちになったら登録した指示を一度だけ送ります（登録しただけではセッションは開きません）。開いたセッションはふつうのセッションと同じで、自動では閉じません（不要になったら自分で閉じてください）。定義・`lastSlot`・実行履歴（結果と開いたセッション名）は `dataDir/routines.json`（version 2）のみへ保存されます。設計は [routines-new-session](docs/handoff/routines-new-session/design.md)（v0.7.0 の [routine design](docs/handoff/v0.7.0-routines/design.md) の一部を置き換え）を参照してください。

## 予約（v0.21.0）

日付と時刻（日本時間）を決めて、その時刻に新しいセッションを1つ開き、指示を1回だけ送る。画面の「予約」タブから登録・取消ができる（取消は「待機中」のものだけ）。正本は `dataDir/reservations.json` で、書くのはサーバーだけ。

- 作業場所は打たずに選ぶ（v0.24.0）。本店で動く役割（Opus 設計役・シェル）は欄が無く「本店（いつもの作業場所）で動きます」と出て、本店で起動する。作業用コピーで動く役割（Sonnet 実装役）は「作業用コピー」の一覧（`GET /api/resume-targets` の worktree の行）から名前（ブランチ）で選び、選んだものの branch を自動で記録する。定期実行タブの新規作成も同じ。定期実行の編集画面は今までどおり役割・作業場所・ブランチを変更不可で表示する。
- 時刻が来ると、Claude が入力待ちになるのを待って指示を貼って Enter を送る。120 秒待っても準備できなければ送らず「送れなかった（準備できず）」と残す。開いたセッションは自動では閉じない。
- 開いた会話は Claude 側の名前も同じにする（Claude の自動の名前で上書きされないよう、指示を送る前に名前を付ける。v0.29.0）。
- アプリが止まっていて時刻を過ぎた予約は、起動後に復元が終わってから1回だけ遅れて送る。送信中に止まったものは再送せず「中断」にする。
- 予約の作成・取消・開始（時刻が来て開くこと）は、`dataDir/routine-audit.jsonl` に1行ずつ残る（`reserveCreate`・`reserveCancel`・`reserveDispatch`。書けなければ作成・取消は失敗し、開始は60秒後にやり直す）。役割の設定 `reservable: false` の役割は、予約の選択肢に出ず、予約の入口でも400になる。

### ac-reserve の使い方（AI が Bash で打つ）

**使ってよいのは、変更の効果を実地で測る予約だけ（PO 決定 2026-10-14）。**

```
node "<dataDir>/bin/ac-reserve.mjs" add < reservation.json
node "<dataDir>/bin/ac-reserve.mjs" list
node "<dataDir>/bin/ac-reserve.mjs" cancel <id>
```

- reservation.json の形: `name`（1〜40字）、`roleId`、`cwd`（本店で動く役割なら省ける。省くと本店になる）、`branch`（worktree 役のとき）、`date`（YYYY-MM-DD）、`time`（HH:mm、日本時間）、`promptText`（8192字以下）、`purpose`（必ず `"measure"`）、`measureNote`（何を測るか、1〜200字）。
- 予定は1分後から366日後まで。待機中の予約は全体で50件、AI の分は20件まで。
- 呼び出し元のセッションの役割が `reserveRoles`（既定 `["opus-designer","shell"]`）に無いと403（名乗りは環境変数 `CLAUDE_CODE_SESSION_ID` から自動で付く）。起動直後は数秒〜数十秒待って再試行する。
- AI の予約は、ほかの待機中の予約・有効な定期実行と開始が60分未満なら400で拒まれ、空いている近い時刻（前・後）が示される（ちょうど60分は通る）。画面からの予約には関門をかけない。
- 画面から予約を作るときは、ほかと開始が60分未満なら確認の欄に知らせる（保存は止めない）。
- 宛先は `dataDir/reserve-token`（`{port, token}`、サーバーが本番のポートで起動したときだけ作る）。失敗は終了コード1と理由を標準エラーに出す。

### ac-routine の使い方（AI が Bash で打つ。Opus 限定）

AI（役割が `routineManagerRoles`、既定 `["opus-designer"]` のセッションの Opus）が、定期実行を登録・変更する。

```
node "<dataDir>/bin/ac-routine.mjs" list
node "<dataDir>/bin/ac-routine.mjs" add < routine.json
node "<dataDir>/bin/ac-routine.mjs" update <id> < routine.json
node "<dataDir>/bin/ac-routine.mjs" enable <id> < reason.json
node "<dataDir>/bin/ac-routine.mjs" disable <id> < reason.json
```

- routine.json: `name`、`roleId`、`cwd`（本店で動く役割は省略可）、`branch`（worktree 役のとき）、`weekdays`、`timeHHmm`、`promptText`、`enabled`、`reason`（1〜200字）。reason.json は `{"reason": "..."}`。削除はできない（止めるのは disable）。役割・cwd・branch は変えられない。
- 関門: AI が作る・変更する・有効にする定期実行は、待機中の予約や、ほかの有効な定期実行と開始が60分未満なら400で拒まれ、空いている近い時刻が示される（画面からの操作と、無効にする操作にはかけない）。
- 画面から定期実行を作る・変えるときは、ほかと開始が60分未満なら確認の欄に知らせる（保存は止めない）。
- 上限: AI が作った定期実行の有効は10件まで（11件目の add は400）。画面で作った分も update/enable/disable できるが、そのたびに `dataDir/routine-audit.jsonl` に「いつ・どの会話・どの役割・理由・結果・対象の作成者」が1行残る。
- 失敗: 終了コード1と理由を標準エラーに出す。起動直後で会話が見つからないときは403になるので、数秒〜数十秒待って再試行する。役割が違う・アプリ外のターミナル・サブエージェントからは拒否される。
- 導入後に `node scripts/ac-hooks.mjs install` をもう一度実行する（guard hook を設定に足す。実行するまでサブエージェントの拒否は効かない）。guard は ac-routine の実行時だけ起動し、通すときは何も出力しない。

#### v0.34.0 の強化（設計: docs/handoff/ac-hardening/design.md）

- **担当が動いている間は書き込みを止める（第1層）**: 呼び出した会話で担当（サブエージェント）が running のとき、add / update / enable / disable は 403 になる（list は通る）。担当が終われば通る。
- **承認で通す**: 止まったら、Opus は `node "<dataDir>/bin/ac-routine.mjs" approve --reason <理由>`（理由 1〜200 字）で、次の書き込み 1 回だけを通す一時承認（10 分・1 回限り）を出す。画面からは、右の「作戦ボード」タブの「ルーティンの変更を 1 回承認する」ボタン（30 分・1 回限り、残り時間を表示）。承認は 1 セッション 1 件で、後から出した方が上書きする。承認は次の書き込み 1 回で（担当がいなくても）消える。発行と使用は `routine-audit.jsonl` に残る（approvalIssued、approvedBy）。担当からの `approve` は guard が拒否する。
- **guard の強化（第2層）**: 担当（`agent_id` あり）の Bash が ac-routine の実行・reserve-token・`Application Support/agent-console` に触れる、または 127.0.0.1 / localhost の routines 系の API を叩く場合と、Read が `Application Support/agent-console` を読む場合を拒否する。hook は 6 規則に分けた `if` 付きで 15 本になる。Grep と Glob は `if` が効かないため対象外。
- **自動クローズ（`closeWhenIdle`、既定 false）**: 定期実行の入力欄「終わったら自動で閉じる」（`ac-routine` の routine.json にも `closeWhenIdle: true` を書ける）。指示を送ったあとから数え、idle が連続して累計 10 分で閉じる。busy / waiting / 不明 / 取得失敗 / 担当が動いている間は 0 からやり直す。waiting のまま 60 分で「閉じずに残した」を 1 回だけ記録する。最後の返答に `NEEDS_DECISION:` か `BLOCKED:` があるとき、返答が 1 件も無いときは閉じずに残す（kept）。閉じたときは返答の先頭 500 字を履歴に残す。closed / kept は監査にも 1 行ずつ残る（token と指示文は書かない）。再起動しても、送ってから24時間以内で閉じていないセッションは見張りに戻る（v0.36.0）。

#### 本番サーバーの停止の見張り（v0.42.0）

`pkill -f "dist-server/server/index.js"`・`pkill node`・`killall node` のように名前で止める命令や、`kill $(lsof -ti tcp:4319)`・`launchctl stop local.agent-console.server` のように本番（127.0.0.1:4319）を狙う命令を、担当にも Opus 本体にも拒否します（hook は `hooks/server-kill-guard.mjs`、同期、`if` は `Bash(*kill*)` と `Bash(*launchctl*)` の 2 本で、hook は計 19 本）。試験サーバーは `lsof -ti tcp:4329 | xargs kill` のように番号で止めます（これは通ります）。`launchctl kickstart`・`print` や `tmux ... kill-session` も通ります。設計は [design](docs/handoff/server-kill-guard/design.md)。

- 導入後に `node scripts/ac-hooks.mjs install` をもう一度実行する（実行するまで拒否は効かない）。

#### 限界（この強化で防げないこと）

- 防げるのは「担当が running の間に会話が書き込む」ことと、担当が guard の対象の道具で ac-routine・reserve-token に触れることまで。設計 §1 の表の (d2)（guard の対象外の道具・間接的な呼び出し）、(e)（担当が起動していない経路）、(h)（Opus 自身が承認して通す正規の経路）は残る。R3（hook の取りこぼし）も残る。
- 第0段の実測（U2）: 担当が動いている最中に中断（SIGINT）や親の終了（SIGTERM）が起きると、SubagentStop も Stop も来ず、running は 24 時間の上限まで残る。その間の書き込みは 403 のままだが、Opus の承認（approve）で越えられる。auto mode に拒否された担当の呼び出しは、すぐ動作中から外れる（v0.36.0。更新後に ac-hooks install を1回）。
- 導入後に `node scripts/ac-hooks.mjs install` をもう一度実行する（guard の `if` を 6 規則に分けて足す。実行するまで第2層は効かない）。
- 本番サーバーの停止の見張り（v0.42.0）は、引用符の分割・変数経由・`kill <pid>` の番号直書き・スクリプトファイルに書いての実行で迂回できる（うっかり防止の水準）。
- 本番サーバーの停止の見張り（v0.42.1 以降）は、引用ヒアドキュメントの本文と単一引用符の中は見ない（`bash <<'EOF'` で流す形は防げない）。
- 自動クローズの idle 判定は `claude agents --json` の定期取得（`agentsPollMs`）の標本で数える。取得が続けて失敗すると閉じない。
- 標本の間が gapLimitMs（既定 60 秒）を超えたとき（Mac のスリープなど）も、取得失敗と同じく 0 から数え直す（v0.35.0）。

## v0.9.0 セッションの様子の記録

左でセッションを選ぶと、右の欄の「作戦ボード」（v0.11.0 までは「このセッション」）に、動いている担当・計画（KGI・KPI・ロードマップ。v0.12.0 から）・タスク（v0.14.0 から）・最近の入力が出ます（台帳は隣の「台帳」タブ）。v0.14.0 で「今の状態」の欄はなくなりました（左の一覧のバッジが正本）。v0.12.0 で「終わった担当」と「やること」の欄はなくなりました。Claude Code の hook が `dataDir/activity/events-YYYYMMDD.jsonl`（UTC の日付、権限 600）に 1 行ずつ追記した記録を、アプリが読んでまとめます。設計は [design](docs/handoff/v0.8.0-activity/design.md)、工程0の実測は [step0](docs/handoff/v0.8.0-activity/step0.md)。

### 入れる（1 回だけ・実行する人が自分で）

アプリは Claude の設定を書き換えません。次を実行すると、`~/.claude/settings.json` に記録用の hook（10 のイベント。v0.11.0 で Stop と StopFailure、v0.12.0 で SubagentStart、v0.36.0 で PermissionDenied が増えました）と、ac-routine のサブエージェント拒否 hook（v0.25.0、v0.33.0 で 6 規則に分割）、作戦ボードの書き忘れ防止 hook（board-guard、v0.32.0、計 17 本）を足します。足す前に控え `settings.json.ac-backup-<日時>` を作り（新しい 6 つだけ残します。1 回の install で控えが 2 つ作られます: hooks の段と statusLine の段）、足すのは自分の hook だけです。足りないイベントを足し、自分の hook の matcher（どの道具のときに動くか）が古ければ直します。2 回実行しても増えません。

```
node scripts/ac-hooks.mjs install      # 足す（hook の本体を dataDir/hooks/ に置いてから、設定に足す）
node scripts/ac-hooks.mjs check        # 入っているか点検する（入っていれば終了コード 0、外れていれば 1）
node scripts/ac-hooks.mjs uninstall    # 自分の hook だけを外す（ほかの設定には触れない）
```

`--settings <settings.json>` と `--data-dir <dataDir>` で場所を変えられます。書き直した設定は JSON として整形し直されます（1 行の配列が複数行になることがあります。元の中身は控えにあります）。hook は Claude を待たせず（async）、失敗しても Claude を止めません。残すのは担当の説明・結果の先頭 120 字・やることの題名などの決めた項目と、v0.11.0 からは入力と Claude の返事の全文（チャット画面の会話のため。1 行 64KiB まで）で、手元のファイルから外へは送りません。全文を残すので、貼った文章に秘密が入っていれば、それも `dataDir/activity/` に残ります（権限 600・7 日で消えます）。

### 「記録の仕組みが外れています」と出たとき（直し方）

settings.json に hook が無い、または node や hook のファイルが無いときに、右の欄にこの案内が出ます（API を呼ぶたびに点検します）。`node scripts/ac-hooks.mjs check` で理由が分かります。`node scripts/ac-hooks.mjs install` を実行し直せば直ります（node の版が変わってパスが消えたときも同じ）。サーバーの起動のとき（本番のポートのみ）に hook の本体が `dataDir/hooks/` に写され、起動のときと 1 時間ごとに点検結果がログに出ます。

### 設定キー

- `reserveRoles`: ac-reserve（AI による予約）を使ってよい役割の id（既定 `["opus-designer","shell"]`。roles に無い id は起動時エラー）。
- roles の各要素の `reservable`: `false` ならその役割は予約で選べない（画面の選択肢から外れ、予約の入口で400）。省くと選べる。
- `claudeSettingsPath`: 「記録の仕組みが外れていないか」の点検で読む Claude の設定ファイル（既定 `~/.claude/settings.json`。読むだけで、アプリは書き換えません）。
- `activityKeepDays`: 記録を残す日数（既定 7）。

### 割り切り

- アプリが読むのは今日と昨日（UTC）の記録だけです。そのため、2 日以上前に呼んだ担当は、アプリを再起動したあとには出ません。
- 古い記録（`activityKeepDays`、既定 7 日より前の日付のファイル）は、本番のポートのサーバーだけが消します。
- 担当がさらに呼んだ担当（孫）は記録しますが、画面には出しません。担当の会話の中身（transcript）は読みません。
- 人の入力かどうかは見分けられないため、見出しは「最近の入力」です（担当の報告の戻りだけは除きます）。

## v0.13.0 作業中でも送れる（送信の予約）

チャットの「送る」は、Claude が作業中でも押せます。押した文章は、アプリ（サーバー）のメモリに「予約」として入り、会話の一番下に並びます（確認待ち・状態不明の間は「予約中（確認が終わったら送ります）」の印がつきます）。**Claude が作業中のときも、送った文章はすぐ端末に入ります（v0.19.0）。作業中に送った文は会話に出ますが、Claude が読むのは作業の区切りです。確認待ち・状態不明の間に送った文章だけは予約され、確認が終わってから届きます。**

- 待機（idle）か作業中（busy）で、許可・質問の待ちが無いことをサーバーが確かめたときに、古い予約から 1 件ずつ端末に書きます（括弧付きで貼ってから、設定の `pasteSubmitDelayMs` だけ待って Enter）。作業中に書いた文は Claude Code 本体の順番待ちに入ります。確認の待ち・状態不明の間は、端末に何も書きません。許可の確認が出ているときに Enter を送ると「Yes」が押されてしまうため、この作りにしています（調査: [recon](docs/handoff/chat2/recon.md)、v0.19.0 の設計: [design](docs/handoff/chat-busy-send/design.md)）。
- 1 件送ったあとは、Claude が受け取ったことを確かめるまで（作業中か確認の待ちを一度見る、または送ったあとの入力の記録が届くまで。作業中に送った分は、作業中を見ても外れず、入力の記録が届くか待機を見るまで）、次の予約を送りません。送った予約は「送信済み（受け取り待ち）」になり、入力の記録が届くと表示から消えて、会話に出ます。
- 各予約の「取り消す」で取り消せます。送信済みで受け取りを確認できないものも、「受け取りを確認できませんでした。消しますか」から消せます（端末には何も書きません）。セッションを閉じると、そのセッションの予約は捨てます。1 セッションの予約は最大 10 件で、超えると理由が出ます。
- **予約はメモリだけに持つので、アプリを再起動すると消えます**（画面にもそう出ます）。送ったあとに失敗しても、自動では再送しません。
- 素のシェル（Claude がいないセッション）では、予約はすぐ書かれ、括弧なしの本文と Enter が送られます。複数行の文章は 1 行ずつ実行されます。停止中のセッションには予約できません。状態が分からない間は、予約だけして送りません。
- 送信済みの予約を、送る直前（約2秒の間）に取り消すと、貼った文字が Claude の入力欄に残ることがあります。その場合は、端末で消してください。
- Claude の会話の番号が分かる前に送った予約は、送信済みのまま残ることがあります。その場合は、取り消しで消してください。
- 「よく使う指示」は作業中も押せて端末の入力欄へ貼るだけ（許可・質問の待ちでは押せず、理由がバーに出ます）、「変更」「部品」はその場で貼って送る、です。

設計は [design](docs/handoff/chat2/design.md)、調査は [recon](docs/handoff/chat2/recon.md)、工程0の実測は [step0](docs/handoff/chat2/step0.md)。

## v0.12.0 作戦ボード

右の欄の「作戦ボード」に、そのセッションで決めた計画（テーマ・KGI・KPI・ロードマップ）と進み具合、そのセッションで進めるタスクが出ます。上から 動いている担当・KGI・KPI・ロードマップ・タスク・最近の入力 の順です。タスクは「進行中」「これから」「完了」の 3 つの組に分かれ（0 件の組は出ません）、上に「完了 N / M」の進み具合が出ます。「完了」の組は最初は閉じていて、押すと開きます。計画を書き込めるのは、そのセッションの Claude だけです（画面から書き換える口はありません。設計書から自動で読み取ることもしません）。画面は計画を 5 秒ごとに取り直すので、書き込んだ内容は 5 秒以内に出ます。最後に書き込んだ時刻（「最後に更新: 3分前」）は KGI の枠の下に出ます。まだ書き込まれていないセッション（Sonnet の役割のセッションや、`/clear` のあと）には「まだ計画が書き込まれていません」と出ます。設計は [design](docs/handoff/board/design.md)、調査は [recon](docs/handoff/board/recon.md)、工程0の実測は [step0](docs/handoff/board/step0.md)。

### 動いている担当（再開したときも出る）

担当を呼んだとき、そして再開したとき（SendMessage など）に、Claude Code の SubagentStart が起きます。これを記録して、再開した担当を「動いている担当」に戻します（v0.11.0 までは、再開した担当が「終わった」に出たままでした）。呼び名・頼んだ仕事の説明・動き始めてからの時間（再開した担当は再開から）が出ます。Agent の呼び出しと結べない担当（Claude の内部の担当、担当がさらに呼んだ担当）は出しません。

### ac-board の使い方（Claude が Bash で打つ）

サーバーが起動するとき（本番のポートのみ）、命令の本体が `dataDir/bin/ac-board.mjs`（この Mac では `~/Library/Application Support/agent-console/bin/ac-board.mjs`）に写されます。Claude は自分で Bash から、標準入力の JSON で打ちます。**ボードは丸ごと書き換わります**（一部だけの書き換えはありません。KGI だけ直したいときも、全部を書いて渡します）。

```
node "$HOME/Library/Application Support/agent-console/bin/ac-board.mjs" write <<'JSON'
{
  "theme": "右の欄を作戦ボードにする",
  "kgi": [{ "text": "PO が画面で、動いている担当と計画と進み具合を見分けられる" }],
  "kpis": [{ "name": "試験の数", "target": "100", "current": "40", "unit": "件" }],
  "roadmap": [
    { "title": "設計", "status": "done" },
    { "title": "実装", "status": "doing" },
    { "title": "導入", "status": "todo" }
  ],
  "tasks": [
    { "title": "試験を書く", "status": "done" },
    { "title": "実装する", "status": "doing" },
    { "title": "導入する", "status": "todo" }
  ]
}
JSON
```

- 自分の会話の番号は、Claude Code の環境変数 `CLAUDE_CODE_SESSION_ID`（Bash の子プロセスと hook に自動で入ります）から取ります。引数では受け取りません（別のセッションのボードに間違って書かないため）。書き込み先は `dataDir/boards/<会話の番号>.json` の 1 か所です（ディレクトリ 700・ファイル 600）。アプリを再起動・更新しても残ります。
- 形（version 1）: `theme`（文字列）・`kgi`（`{text}` の配列）・`kpis`（`{name, target, current, unit}` の配列。値はすべて文字列）・`roadmap`（`{title, status}` の配列。`status` は `todo`・`doing`・`done` のどれか）。`tasks`（`{title, status}` の配列。このセッションで進める仕事の単位。担当に任せた仕事も含める）。`tasks` だけは省けます（省いたら 0 件。v0.14.0 から。version は 1 のまま）。ほかの 4 つは必須で、これ以外の項目は書けません。v0.14.0 以降が書いた `tasks` 付きのファイルは、v0.13.0 以前では読めません（前の版へ戻すときは `tasks` を外して書き直します）（`version` と `updatedAt` は命令が付けます）。
- 上限（文字数は 1 文字を 1 と数えます）: `theme` 200 字、`kgi` 10 件で各 500 字、`kpis` 20 件で各項目 200 字、`roadmap` 50 件で各 200 字、`tasks` 100 件で各 200 字、入力全体 256KiB。`theme`・`kgi.text`・`kpis.name`・`roadmap.title`・`tasks.title` は空にできません（`target`・`current`・`unit` は空でも構いません）。改行とタブ以外の制御文字は拒否されます。
- 形が違う・長すぎる・制御文字があるときは、何も書かずに理由を標準エラーに出して、終了コード 1 で終わります。書き込めたときは終了コード 0 です。
- ロードマップの進み具合は「`done` の数 / `roadmap` の数」、タスクの進み具合は「`done` の数 / `tasks` の数」です。KPI の「今の値」が変わったとき、段階の状態が変わったときも、同じ命令で全部を書き直します。

### /clear のときと、番号を付けずに再開したとき

- `/clear` をすると会話の番号が変わり（Claude 公式の仕様）、画面も新しい番号を指すので、**新しい（空の）ボード**になります。前のボードは引き継ぎません（ファイルは `dataDir/boards/<前の番号>.json` に残ります）。必要なら、新しい会話で Claude にもう一度書いてもらいます。
- 番号を付けずに過去の会話を再開したとき（`claude --resume` の選ぶ一覧、`claude --continue`）、公式の文書は「環境変数の番号が起動のときの番号のままになりうる」と書いています。**この版（Claude Code 2.1.296）で実機で確かめたところ、どちらも食い違いませんでした**（環境変数・hook の session_id・Bash の出力が、再開した会話の番号と同じ）。食い違ったときは、ボードが別の番号に書かれて画面に出ません（工程0 (b)、[step0](docs/handoff/board/step0.md)）。アプリが番号を付けて復元する再開は対象外です。

### 更新したあとにやること（hook を入れ直す）

再開の印（SubagentStart）を記録するために、記録するイベントが増えました。**v0.11.0 までに `node scripts/ac-hooks.mjs install` を済ませている人も、更新のあとにもう一度実行してください**（足りない 1 つだけが足されます。すでに入っている 8 つや、ほかの設定は変わらず、足す前に控えを作ります）。実行するまでは、右の欄に「記録の仕組みが外れています」と出て、再開した担当は「動いている担当」に戻りません。

```
node scripts/ac-hooks.mjs install
node scripts/ac-hooks.mjs check
```

## v0.20.0 更新しても会話が続く（tmux 保持）

各セッションの本体（claude）は、このアプリ専用の tmux サーバー（`tmux -L agent-console`、設定は `ops/tmux/agent-console.tmux.conf`）の中で動きます。アプリ（サーバー）を更新・再起動しても本体は止まらず、起動時に同じセッションへつなぎ直します（`--resume` で開き直さないので、作業中でも切れません）。起動のログに `open-sessions: つなぎ直し N・resume M` が出ます。設計は [design](docs/handoff/keep-sessions/design.md)。

- **tmux が必要です**（`brew install tmux`）。見つからない時は今までどおりの方式（direct）で動き、画面に案内が出ます（その場合、更新するとセッションは閉じます）。
- **×で閉じる**と、tmux のセッションも本体も終わります。「一覧から外す」などの今までの操作は変わりません。
- **tmux の版が合わない時の直し方**: 設定は tmux サーバーの起動時に 1 回だけ読まれます。tmux を入れ替えたあとなどで動きがおかしい時は、全セッションを閉じて開き直してください（セッションが 0 件になると tmux サーバーも終わり、次の起動で新しい設定を読みます）。
- **前の版へ戻した時（切戻し中）の見方と注意**: 戻す先が tmux を知らない版（v0.19.0 以前）の場合、`scripts/ac-update.sh` の失敗時の戻しと `scripts/ac-rollback.sh` は、保存リスト（`open-sessions.json`）と routine（`routines.json`）を `*.tmux-held.json` へ退避してから戻します（同じ会話を二重に起動しないため。この間 routine の予定は止まります）。「裏で N 件が動いています。この間は会話を開き直さないでください」と出たら、その間は同じ会話を手で開き直さないでください。裏で動いている会話は `tmux -L agent-console attach -t =<名前>`（名前は出力に一覧が出ます）で見られます。tmux を知っている版へ更新すると、退避したファイルを今のリストと合わせて元へ戻し、画面につなぎ直します。
- 試験: tmux の統合試験は本物の tmux を使います（`tests/unit/tmux-host.integration.test.ts`）。試験用の config は `terminalHost: "direct"` か専用ソケットにして、本番のソケットを使わないでください。

## v0.26.0 ファイルタブ（セッションが書いたファイルを読む）

中央のタブ「変更」の隣の「ファイル」に、選んだセッションが Write・Edit・MultiEdit・NotebookEdit で書いたファイル（担当が書いたものも。「担当」の印が付きます）が、新しい順に出ます。押すと中身が右に出ます。`.md` は見出し・表などを整えて出し（リンクは http・https のものだけ開けます）、それ以外は文字のまま出します。読むだけで、書き換えはできません。1 MiB を超えるもの・文字でないもの・消されたもの・普通のファイルでないもの（リンク・フォルダ）は、中身を出さず理由を出します。設計は [design](docs/handoff/file-viewer/design.md)、調査は [recon](docs/handoff/file-viewer/recon.md)。

## v0.32.0 作戦ボードの書き忘れ防止（board-guard）

作戦ボードを書かないまま作業を進めているセッションを、**応答が終わるとき（Stop）に 1 回だけ止め**、書き方（`ac-board` のコマンドと JSON の形・上限）を本人に渡します。設計は [design](docs/handoff/board-guard/design.md)（§13 が最優先）。

- 止めるのは、このアプリが開いたセッション（`open-sessions.json` に会話の番号があるもの）だけです。アプリの外で動かした Claude は止めません。
- 止める条件は、ボードが無い（または形が壊れている）こと、かつ会話の記録（transcript）に道具の呼び出し（tool_use）が 3 件以上あることです。単発の質問だけのセッションは止まりません。止めたあと「theme だけ書けばよい」と案内します。
- 止めるのは各セッションで 1 回だけです（止めた印は `dataDir/board-guard/<会話の番号>`）。書かなくても 2 回目以降は止めません。復元の直後は、ボードの無いセッションが次の応答終了で 1 回ずつ止まります。新しいセッションの最初の応答は、番号がまだ保存されていなければ止まらず、次以降の応答で止まります。
- どこで失敗しても止めません（終了コード 0・出力なし）。失敗は `dataDir/board-guard/errors.log` に日時つきで 1 行残ります。
- 保有率（ボードがあるセッション ÷ 開いているセッション）は `node scripts/board-coverage.mjs` で測れます（読むだけ。「ok 件数/全件数（日時）」を 1 行で出します）。

### 更新したあとにやること（hook を入れ直す）

board-guard の hook（Stop・同期）が増えました。**v0.31.0 までに `node scripts/ac-hooks.mjs install` を済ませている人も、更新のあとにもう一度実行してください**（足りない 1 つだけが足されます。すでに入っている 10 本や、ほかの設定は変わらず、足す前に控えを作ります。install は board-guard の本体を `dataDir/hooks/` に、判定の正本の `ac-board.mjs` を `dataDir/bin/` に写してから登録します）。

- 実行するまでは、右の欄に「記録の仕組みが外れています」と出ます（点検が board-guard の欠けを理由にするため）。**記録用の hook と ac-routine の guard は動き続けています**が、**ボードの案内（board-guard）は install するまで働きません**。
- install のあと、すでに動いているセッションに効くかは確かめていません。効かないときは、そのセッションを開き直してください（hook は起動時に読まれます）。

```
node scripts/ac-hooks.mjs install
node scripts/ac-hooks.mjs check
```

## 使い方（毎日の操作）

- **作業の区切りの通知**: Claude の状態が「作業中」から「回答待ち」または「指示待ち」に変わると、一覧の行に「未読」の印、窓のタイトルに未読数、macOS の通知が出ます。行を選ぶと未読が消えます。この「区切り」はこのアプリの定義で、Claude 公式の「ターン完了」ではありません。macOS 通知は設定 `notify.macos`（既定 true）で切り替えます。
- **名前の変更**: 一覧の名前をダブルクリック、または行を選んだ状態で F2 キー（Mac では Fn+F2 のことがあります）。Claude 起動中は Claude に `/rename` を送ります。指示待ちのときはすぐ、作業中・許可待ち・状態不明のときは端末に何も書かずに予約し（行に「予約: 名前」が出ます）、指示待ちになったら自動で1回送ります（許可待ちの間には送りません。予約はメモリだけで、サーバーを再起動すると消えます）。指示待ちのときに送って10 秒たっても名前が変わらなければ画面に案内が出ます。Claude が動いていないセッションは、このアプリでの表示名を変えます。
- **よく使う指示**: 端末の上のバー（1 行）には、「常に表示」にした指示のボタンだけが並びます（入りきらない分は折り返さず、横に動かして見ます）。バーのボタンは左の「よく使う指示」と、常に表示の指示だけです（「指示を編集」のボタンはありません）。左の「よく使う指示」を押すと、1つの画面が開きます（Esc で閉じます）。各行の「使う」で選択中の端末の入力欄に入れ、「常に表示」でバーに出す・出さないを切り替え（閉じなくてもバーに反映されます）、「編集」「削除」と、下の form での追加ができます。新しく作った指示は「常に表示」です。各行の「↑」「↓」で1つずつ上下に動かせ（先頭の「↑」と末尾の「↓」は押せません）、バーのボタンも同じ順に並びます。ボタンは Claude の作業中も押せます（許可・質問への返事待ち、セッション停止中、状態不明のときは押せず、理由がバーに出ます）。押すと、選択中の端末の入力欄に文章を入れます（Enter は送りません。送るのは端末で Enter を押したとき。8KB まで）。保存先は `~/Library/Application Support/agent-console/quick-prompts.json`（設定 `dataDir` で変更、権限 600）の 1 ファイルだけです（各項目の `pinned` が「常に表示」の印。version は 1 のまま）。
- **セッションの行と並び順**: 左の一覧の行は、1段目に状態の丸・名前、2段目に役割・状態の印・未読の印・CI の印・予約の名前が出ます。行をドラッグして離すか、行を選んで Alt+↑ / Alt+↓ を押すと並び順が変わります。並び順は再起動のあとも残ります（復元のリストの順）。
- **変更内容の表示と、行ごとのコメント**: 端末の上の「変更」タブで、選んでいるセッションの作業場所（本店か worktree）の、基準 `origin/main`（設定 `diffBaseRef`。最後に取得した状態で、アプリは fetch しません）から変わったファイルを一覧できます（コミット済み・未コミット・まだ追加されていないファイル）。ファイルを押すと行番号つきの変更が出て、追加行は緑、削除行は赤の背景です。行を押すとコメント欄が開き、保存すると印がつきます（編集・削除できます。ファイル全体へのコメントもできます）。コメントは `~/Library/Application Support/agent-console/diff-comments.json`（権限 600）に残り、worktree が消えると、その場所の分も消えます。「Claude に送る（N件）」で、未送信のコメントを `File／Line／該当行／Comment` の 1 つの文章にして端末へ貼り、`pasteSubmitDelayMs`（既定 2000 ms）待ってから Enter を送ります。Claude が作業中・許可の確認待ちのときは押せず、理由がボタンの横に出ます。待っている間に別のセッションへ切り替えると、Enter は送らず「貼り付けましたが送っていません」と出ます。1 ファイルの変更が `diffMaxFileBytes`（既定 1 MiB）を超えるファイルと、バイナリは中身を出しません。送る文章の上限は `diffSendMaxBytes`（既定 16 KiB）です。本店でも worktree でもない場所のセッションでは git を実行せず「この作業場所の変更は表示できません」と出ます。
- **PR と自動検査（CI）の状態**: 端末の上の「PR」タブで、選んでいるセッションの作業場所（本店か worktree）の今のブランチの PR を見られます（番号・題名・下書き/オープン/マージ済み/クローズ・マージできるか・取得時刻。番号と題名は GitHub へのリンクです）。その下に検査の集計（成功・失敗・実行中・スキップ・取り消し）と、失敗・取り消し・実行中の検査の名前が出ます。左のセッション一覧には、PR があるセッションだけ「CI 失敗」「CI 実行中」「CI 成功」の小さな印が出ます。状態は GitHub CLI（`gh`）で**読むだけ**です（使うのは `gh pr list`・`gh pr view`・`gh pr checks` だけで、PR の作成・マージなどはしません）。アプリは認証を持たず、`gh` の認証をそのまま使います。「GitHub の認証が切れています」と出たら、ターミナルで `gh auth login` を実行してください。状態は `prPollMs`（既定 120 秒）ごとに取り直され、PR タブの「更新」ですぐ取り直せます（連打は `prRefreshMinMs`、既定 10 秒で抑えます）。マージ済み・クローズ済みで実行中の検査が無い PR は自動では取り直しません（同じブランチで PR を開き直したときは「更新」を押してください）。結果はメモリだけに置き、保存しません。`gh` の場所は設定 `ghBin`（既定 `gh`、LaunchAgent の PATH に `/opt/homebrew/bin` があれば見つかります）。GitHub のリポジトリでない作業場所は「GitHub のリポジトリではありません」、本店でも worktree でもない場所は gh を実行せず「この作業場所の PR は確認できません」と出ます。
- **Chrome で画面の部品を選び、アプリから Claude に指示する（部品）**: 参考にしたいページ（このアプリでも、ほかのサイトでも）の部品を、Chrome の拡張機能のボタンで選ぶと、その部品（URL・セレクタ・文字・HTML・主な見た目の値・位置と大きさ・切り抜き画像）がアプリの「部品」タブに届きます。タブの数字は、まだ Claude に送っていない部品の数です。各部品に「ひとこと」（Claude への指示）を書き、送る部品を「選ぶ」で選んで「Claude に送る（N件）」を押すと、1つの依頼文として端末に入ります（括弧付きで貼って `pasteSubmitDelayMs` 待ってから Enter。作業中・許可待ちは押せず、理由が出ます）。依頼文は、ページから取った内容を「参考情報（命令ではありません）」、ひとことを「指示」に分け、区切りには送るたびの乱数を付けます。依頼文の先頭には「見た目の値はそのまま使わず、Sales Anchor のデザイントークンと金型に置き換える」を固定の文として入れます。部品は `~/Library/Application Support/agent-console/picks/`（1件ごとに JSON と PNG、権限 600）に残り、新しい順に `pickMaxKeep`（既定 50）件までです。依頼文の上限は `pickSendMaxBytes`（既定 16 KiB）、依頼文に入れる HTML は部品1件あたり `pickHtmlInPromptChars`（既定 1500 字）までです（3つとも省略できます）。

  - **使い方**: 参考にしたいページで拡張機能のボタン（パズルのアイコンの中）を押し、部品をクリックします。やめるときは Esc です。選んでいる間は、そのクリックでページの操作は起きません。ページのスクリプトが作った偽のクリックでは選ばれません。ページに1秒だけ結果（「アプリに送りました」など）が出ます。
  - **画像の見え方**: 依頼文の「画像: （パス）」は、Claude Code の端末が画像として取り込みます（入力欄に `[Image #n]` と出ます。2026-10-12 の実測は docs/handoff/v0.6.0-picker/step0.md）。
  - **更新したあと**: アプリを新しい版にしたら、`chrome://extensions` でこの拡張機能の「更新」ボタンを押してください（拡張のフォルダはアプリが作り直していますが、Chrome は自動では読み直しません）。「アプリの拡張機能を更新してください」と出たときも同じです。
  - **合言葉の作り直し**: 拡張とアプリは、`~/Library/Application Support/agent-console/picker-token`（権限 600）の合言葉で結ばれています。作り直したいときは、そのファイルを削除してアプリを再起動し、`chrome://extensions` で拡張機能の「更新」を押します（ボタンはありません）。

  - **できないこと**: iframe の中の部品は選べません（最上位のフレームだけ）。切り抜き画像は、いま見えている範囲だけです。`chrome://` など Chrome の内部のページでは動かず、ボタンに「×」が出ます。React の部品名は取りません。

- **セッションの引き継ぎ（v0.30.0）**: 一覧の行の「次のセッションへ引き継ぐ」（矢印が左右に並んだアイコン）を押して確認すると、今のセッションに引き継ぎ書を `relayDir`（設定に無ければ `~/CC報告ファイル-keep/relay`。`AGENT_CONSOLE_PORT` を指定したサーバーは設定した場合だけ）の `<日本時間の年月日-時分秒>-<id先頭8桁>/HANDOFF.md` へ書かせ、できたら名前の末尾の数字を 1 つ増やした新しいセッションを同じ作業場所・同じ役割で開いて続きを渡します（末尾が「MM/DD HH:mm」なら " 2" を付けます）。古いセッションは閉じません。入力待ちでないとき・送った文の確認待ちや名前の変更の予約が残っているときは始められません（409）。失敗すると画面に理由を出し、開いたセッションは残ります。文を送っている間は別の経路の `/rename` を書かず（書き込みの印）、新しく開いたセッションは最初の入力待ちで `/rename` により名前を合わせます。
- **一言も入力していないセッションは通常起動になる**: Claude は最初の入力をするまで会話の id が取れないため、一言も入力していないセッションは会話の続きではなく、新しい Claude（通常起動）として開き直されます。端末の画面の中身（スクロールの履歴）や、作業の途中だった指示は復元しません。
- **復元の無効化（`AGENT_CONSOLE_RESTORE=off`）**: この環境変数が文字列の `off` のときだけ、起動時の復元と復元リストの読み書きをしません。更新時の自己診断サーバーは本番と同じ dataDir を読むため、`ac_diagnose` が付けて起動します（未設定なら有効）。
- **ポートを上書きしたサーバーは復元しない**: `AGENT_CONSOLE_PORT` を指定して起動したサーバー（自己診断・試験・検証用）は、`AGENT_CONSOLE_RESTORE` に関係なく復元も復元リストの記録もしません。本番の自動起動（LaunchAgent）は `AGENT_CONSOLE_PORT` を使わないので影響しません。
- **台帳ボードの絞り込み**: 既定は「作業中・レビュー・WIP」かつ「開始日が直近 30 日」です。隠れた件数と、開始日を読めない行（日付不明）の件数が別に出ます。期間・状態・ブランチ名の検索を変えられます（この表示設定はブラウザの localStorage に保存されます）。
- **メモリ**: フッターの「メモリ」で、セッションごと・このアプリのサーバー・Mac 全体を MB と % で見られます（開いている間だけ 10 秒ごとに更新）。

## PO 向け: 導入・更新・切戻し・撤去（この Mac）

どれも PO が `!` を付けて実行する（キーチェーン・LaunchAgent・~/Applications を変更するため、Claude は実行しない）。
`vX.Y.Z` は git タグ（`docs/CHANGELOG.md` に載っている版）。リポジトリのどの場所からでも実行できる（この 4 本は、いま開いているチェックアウトの `scripts/` から呼ぶ）。

| やること | 1 行コマンド | 何が起きるか |
|---|---|---|
| 初回導入 | `! bash scripts/ac-install.sh v0.2.0` | サーバー秘密をキーチェーンに保存 → 版を取得（**タグのコミットが origin/main に含まれることを確認**、`npm ci --ignore-scripts`、**コミット SHA を表示**）・ビルド → **別ポートで自己診断（/healthz の版・コミットが一致）** → ログイン時自動起動を登録 → Dock 用の `~/Applications/Agent Console.app` を生成（アイコン入り。更新・切戻しでも切替先の版の絵で作り直す。icns の無い版は標準の絵） → `/healthz` を確認して結果を表示 |
| 更新 | `! bash scripts/ac-update.sh v0.3.6` | 新しい版を導入（上と同じ検証）→ 自己診断に通ったときだけ切替 → 再起動 → `/healthz` の版・コミットの一致を確認。失敗したら元の版に戻る |
| 切戻し | `! bash scripts/ac-rollback.sh` | 1 つ前の版（semver 順）に切替 → 再起動 → `/healthz` の版・コミットの一致を確認 |
| 撤去 | `! bash scripts/ac-uninstall.sh` | 自動起動と起動アプリを外して **Trash へ移す**（削除しない）。導入済みの版とキーチェーンの秘密は残す |
| 完全撤去 | `! bash scripts/ac-uninstall.sh --purge` | 上に加えて、導入済みの版・current・logs を Trash へ移し、キーチェーンの秘密を削除（秘密の削除だけは元に戻せない） |

- 片付けはすべて `~/.Trash/agent-console-<種類>-<日時>` への移動で、スクリプトは削除コマンド（`rm` を含む）を使わない。戻したいときは Trash から元の場所へ戻す。
- 導入後は Dock に `Agent Console.app`（`~/Applications`）をドラッグして固定する。1 回クリックすると、Chrome のアプリ窓がログイン済みで開く。
- Dock の絵が古いままなら、Dock から `Agent Console.app` を外して付け直す（Dock が古い絵を覚えているため。スクリプトは Dock を再起動しない）。
- 使用中の版とコミットは、画面下部の「版」「コミット」で確認できる。
- 置き場所: `~/Library/Application Support/agent-console/`（`versions/<tag>/`、`current`、`logs/`）、`~/Library/LaunchAgents/local.agent-console.server.plist`、キーチェーンのサービス `agent-console` / アカウント `server`。
- 新しい版が入ったら、目視の前に画面上部の「新しい版が入りました」の「再読み込み」（出ていなければブラウザの再読み込み）を押す。押すまで画面は前の版のままです。
- 新しい版を出す手順: package.json の version を上げる PR → マージ → `vX.Y.Z` タグを付けて push → CHANGELOG に 1 行追記。

## 利用量バー（週・5時間）の設定

画面下の帯の利用量バーは、Claude Code の statusLine の命令が書く `dataDir/usage.json` を読みます。`node scripts/ac-hooks.mjs install` が hook に続けて settings.json の `statusLine` を 1 つ足します（`node scripts/ac-hooks.mjs check` で点検、`uninstall` で自分の statusLine だけを外す）。すでに別の statusLine がある場合は足さず、「statusLine: 別の設定があるので足していません」と出して終了コード 0 で終わります（そのときバーは「まだ値がありません」のまま）。値は Claude の最初の API 応答のあとに来るため、起動直後は出ません。パスに `"`・`$`・バッククォート・`\`・改行を含む dataDir では statusLine を足さず、理由を出して終了コード 1 で終わります（hooks は入ります）。

dataDir を変えたときは、先に旧 dataDir で `ac-hooks.mjs uninstall` を実行してください（または settings.json の statusLine を手で外してください）。自分の物かは、今の dataDir の引用符付きパスで見分けるためです。

## Claude アカウントの切り替え

画面下の帯の「Claude ログイン: メール」は、この Mac に保存された Claude のログインです（サーバーが `claude auth status --json` を毎回聞き、メールとプランだけを画面へ返します。アプリは保存しません）。「アカウントを切り替える」を押して確認すると、「アカウント切り替え」という端末が開き、`claude auth logout; claude auth login`（`agent-console.config.json` の `accountLoginCommand`。無ければボタンは出ません）が動きます。端末の案内に沿ってブラウザでログインし、必要ならコードを端末へ貼ってください。終わったらその端末を「一覧から外す」で消してください（ログイン用の URL やコードが端末の出力に残るため）。端末が終わると、帯の表示が新しいアカウントに変わります。

- **会話ごとの確認は `/status` で行います。** 帯の表示は「この Mac に保存されたログイン」で、会話ごとの実際の認証ではありません。
- **開き直しで切り替わります。** 環境変数 `CLAUDE_CODE_OAUTH_TOKEN` を持つ会話は、`claude auth login` では切り替わらず、開き直すまで起動したときのトークンを使い続けます。開いている会話は、閉じて開き直すと新しいアカウントで動きます。
- **サーバーの環境に `CLAUDE_CODE_OAUTH_TOKEN` を置かないでください。** 置くと、子の会話がすべてそのトークンで動き、帯の表示と食い違います（この変数は子の環境から除外していません）。
- ログインの途中でやめると、ログインし直すまで新しい会話は使えず、開いている会話も止まることがあります。元に戻すときは同じボタンで入り直してください。

## 認証の仕組み（要点）

- サーバー秘密はキーチェーンだけに置く（ファイル・URL・ログに出さない）。**ネットワーク（4319 の相手）にも送らない**。
- 起動アプリは相互認証でサーバーを確かめる: 乱数 `cnonce` を送る → サーバーが `HMAC(秘密, "server|cnonce|snonce")` を返す → 起動アプリが検証（偽のサーバーなら、何も送らず中止）→ `HMAC(秘密, "client|snonce|cnonce")` を送って 1 回限りコード（30 秒で失効）を得る。HMAC の計算に秘密は標準入力で渡す（引数に出さない）。
- 画面は `/pair?code=` でコードを引換え、セッショントークン（最長 12 時間）を**タブの sessionStorage** に保存する。**Cookie は使わない**（Cookie は同じ 127.0.0.1 の別ポートへも送られるため）。API は `Authorization: Bearer`、WebSocket は `Sec-WebSocket-Protocol: ac.<token>`。画面下部の「ログアウト」でサーバー側のセッションを失効させる。
- 開発時（`npm start`）は秘密を使わず、起動ごとの乱数と、起動ログのペアリング URL（5 分）を使う。
- 本番実行では `AC_*` の差し替え環境変数を無視する（テストモード `AC_STUB_LOG` のときだけ有効）。
- 注意: キーチェーンは別ユーザー・ファイルの直読みからの保護で、同じユーザーのマルウェア・端末内のプロセスは対象外（`security` コマンドで読み出せ得る。未検証）。
