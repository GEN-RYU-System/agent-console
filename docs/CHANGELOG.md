- 0.5.0 PR と自動検査（CI）の状態をアプリで見る: 端末の上のタブが「端末」「変更」「PR」の3つになる。「PR」は、選んだセッションの作業場所（本店か worktree だけ。それ以外は git も gh も実行せず「この作業場所の PR は確認できません」）の今のブランチ（正本は `git rev-parse --abbrev-ref HEAD`、repo は `git remote get-url origin` の GitHub の https / ssh 形）の PR を出す: `#番号 題名`（`https://github.com/` で始まる url だけリンク）・状態（下書き／オープン／マージ済み／クローズ）・マージできるか（`mergeStateStatus` を日本語に。open のときだけ `gh pr view` で引く）・取得時刻、検査の集計（成功・失敗・実行中・スキップ・取り消し）、失敗・取り消し・実行中の検査の名前とリンク。左のセッション一覧の各行には PR があるときだけ「CI 失敗」（失敗か取り消しが1件でもある）「CI 実行中」「CI 成功」の小さな印が出る。PR が無いブランチは「このブランチの PR はありません」、GitHub でないリポジトリは「GitHub のリポジトリではありません」、ブランチにいない（detached）作業場所は「ブランチにいないため PR を確認できません」。GitHub へは読むだけで、使う gh は `pr list`・`pr view`・`pr checks` の3つに固定（`server/pr-status.ts` の `runGh` だけが gh を呼び、それ以外は起動前に例外）。gh は execFile（シェルなし・15 秒・4MiB）で、環境に `GH_PROMPT_DISABLED=1` と `GH_NO_UPDATE_NOTIFIER=1` を足す。サーバーは `prPollMs`（既定 120000）ごとに、動いているセッションの (repo, branch) ごとに1回だけ取り直し、結果はメモリだけに置く（保存しない）。マージ済みかクローズで実行中の検査が無い PR は自動では取り直さない（開き直した PR は PR タブの「更新」で拾う）。「更新」は `POST /api/sessions/:id/pr/refresh` で、前回から `prRefreshMinMs`（既定 10000）以内なら今の結果を返す。同じ (repo, branch) の取得が同時に走るときは1本にまとめる。gh が失敗したときは「GitHub の状態を取得できませんでした」と理由（gh が無い・認証切れ=`gh auth login` を案内・時間切れ・利用上限・その他）を出し、利用上限に当たった回は残りの取り直しをやめて次の間隔まで待つ。`GET /api/sessions/:id/pr` はメモリの写しを返すだけで gh を呼ばない（まだ無ければ `loading`）。設定 `ghBin`（既定 `gh`）・`prPollMs`・`prRefreshMinMs` は省略できる。作業場所の照合は `server/workplace.ts` に移して、変更タブと PR で共有（動作は変えない）。設計の正本は docs/handoff/v0.5.0-pr-ci/design.md、gh の実測は同 step0.md。
- 0.4.0 変更内容（diff）の表示と、行ごとのコメントを Claude に渡す: 端末の上に「端末」と「変更」のタブ（SA の Tabs）。「変更」は、選んだセッションの作業場所（本店か worktree だけ。それ以外は git を実行せず「この作業場所の変更は表示できません」）で、基準 `origin/main`（設定 `diffBaseRef`、最後に取得した状態でアプリは fetch しない）から変わったファイルの一覧（コミット済み・ステージ済み・未ステージは `git diff --merge-base <基準> --no-renames --numstat -z`、未追加は `git ls-files --others --exclude-standard -z`）と、1 ファイルずつの行番号つき diff（追加行は `--color-success-bg`、削除行は `--color-error-bg`）を出す。1 ファイルの変更が `diffMaxFileBytes`（既定 1MiB）を超えるときは本文を出さず、バイナリも出さない。行を押すとコメント欄が開き（1 行ずつ・ファイル全体にも 1 つ）、編集・削除でき、`dataDir/diff-comments.json`（権限 600、作業場所ごと。worktree が消えた・別ブランチで作り直された場所の分は読むたびに捨てる）に残る。「Claude に送る（N件）」で未送信のコメントを `File／Line／該当行／Comment` の 1 つの文章にし（`diffSendMaxBytes` 既定 16KiB まで）、画面が端末へ括弧付きで貼り、`pasteSubmitDelayMs`（既定 2000ms。本物の claude で 1 つの依頼になると実測した値）待ってから Enter を送る。Claude が作業中・許可の確認待ちのときは押せず、理由をボタンの横に常に表示する。待っている間にセッションを切り替えたら Enter は送らず送信済みにもしない。画面から渡すファイル名は、サーバーがその時点で作った一覧に完全一致するものだけ受け付ける（取得・コメントの追加と編集）。端末の大きさ合わせは、隠れている（幅か高さが 0）間は pty へ送らない。API: `GET /api/sessions/:id/diff`・`/diff/file?path=`・`/diff-comments`、`POST|PUT|DELETE …/diff-comments[/:cid]`、`POST …/diff-comments/send-check`・`/mark-sent`。設計の正本は docs/handoff/v0.4.0-diff-comments/design.md、貼り付け経路の実測は同 step0.md。
